# Resumable CDP transport, v1

This is an opt-in prototype integrated into kernel-images-api. It retains the guest-local CDP connection while metro-api parks and replaces the host-to-guest transport. It does not restart Chrome, reattach targets, reconstruct CDP state, or request standby itself.

## Ownership

- Metro-api owns the client's original WebSocket.
- This package owns one guest-local WebSocket per logical relay session, independent of HTTP request contexts. It connects through the existing `devtoolsproxy`, preserving its command telemetry and Chrome-restart behavior.
- The middle transport consists of authenticated, short-lived HTTP requests. Polls may be canceled and requests retried without closing either endpoint.
- A real client close sends `DELETE`. Chrome failure, API restart, protocol mismatch, or buffer exhaustion is terminal. Never replace a missing logical session with a fresh Chrome connection.

`CDP_RELAY_TOKEN` enables the private routes on the existing API port. Empty disables them. Supply at least 32 bytes of cryptographically random secret, unique to this instance; metro-api must have the same value. Do not put a shared fleet token into browser images. Logging reports only whether the feature is enabled.

Fork templates are rejected when this setting is enabled: a cloned secret and retained connection registry must not accidentally become another browser's identity. Per-fork key handoff is intentionally not implemented.

## Wire contract

All routes require `Authorization: Bearer <per-instance-token>`. The path is `/internal/cdp-relay/v1/{id}`, where `id` is 32 random bytes encoded as 64 lowercase hexadecimal characters, generated by the host once per client connection.

| Method and suffix | Request | Response |
| --- | --- | --- |
| `PUT /{id}` | none | `{epoch: 0, seq: 0}` for a new logical session; repeats return existing state |
| `POST /{id}/send` | `{epoch, seq, data: <raw CDP JSON>}` | `true` once accepted by the original local WebSocket |
| `GET /{id}/events?epoch=N&ack=N` | none | ordered `[{seq, data}]`; empty array after a 15s long poll |
| `POST /{id}/park` | `{epoch, seq, ack}` | `{epoch: previous+1, seq}` |
| `POST /{id}/resume` | `{epoch, seq, ack}` | `{epoch: previous+1, seq}` |
| `DELETE /{id}` | none | `204`, also when already deleted |

`seq` in command/control messages counts accepted client commands. Event sequence numbers form a separate counter. `ack` is the last event consumed by the host proxy reader. Responses remain buffered until acknowledged. CDP command IDs are tracked together with their flattened `sessionId`; the transport counters are not CDP IDs.

### Retry and fencing rules

- Creation retries use the same random ID. Once attached, the host never calls `PUT` to repair a lost session.
- Commands must arrive sequentially. A retry of the last accepted sequence succeeds only with the same SHA-256 payload digest. Only one command HTTP write is in flight at the host.
- A canceled HTTP request does not cancel the guest-local Chrome write. An ambiguous Chrome write failure terminates the session instead of retrying against Chrome.
- Park waits for in-flight writes, verifies the host's committed command sequence, acknowledges its event boundary, and requires no outstanding CDP responses or unacknowledged events.
- Legacy nested `Target.sendMessageToTarget` disables parking for that logical connection; an outer response does not prove the inner command completed. Ordinary and flattened CDP remain supported.
- Each park/resume advances an epoch. The immediately preceding transition is idempotent; an older control request cannot change a resumed session.
- Events arriving after the park boundary remain buffered for resume. Parking therefore deliberately pauses event delivery, even if other activity keeps the browser awake.
- `423` means busy/capacity exhausted. A busy park is not fatal. `409` means a stale or inconsistent boundary; `404`/`410` means the logical session is gone. None authorizes a fresh Chrome connection.

## Bounds and teardown

Defaults are eight logical sessions, 8 MiB or 4096 buffered output frames per session, and 1024 outstanding CDP commands. Guest-local writes have a 10s deadline. Overflow fails explicitly; messages are never silently evicted.

Active sessions with no host requests expire after two minutes of guest-running time. **Parked sessions do not expire merely because the transport is silent.** They end on explicit deletion, upstream failure, or browser/API teardown. A host crash can therefore leave a bounded parked orphan until browser teardown; the connection limit prevents unbounded retention. This prototype must not be used with reusable browser leases until their teardown owns relay cleanup.

The guest API restart is not transparent: it loses the retained sockets and registry. VM snapshot/restore preserves them; restarting processes does not. Restoring an older snapshot that disagrees with the host's counters fails fencing checks rather than replaying uncertain commands.

## Validation and scope

```sh
go test -race -count=10 ./lib/cdprelay
go test ./cmd/config ./cmd/api ./lib/devtoolsproxy
```

Tests cover retry deduplication, payload conflicts, event replay, park barriers, stale epochs, late events, authentication, capacity, orphan expiry, parked retention, terminal upstream failure, and buffer exhaustion.

The paired metro-api integration test uses a rebuilt kernel-images-api in a disposable Cloud Hypervisor browser and real automatic standby. Both final-code cycles preserved the same Playwright connection, JSHandle, CDP object/context/session IDs, Runtime binding and debugger breakpoint. First-command times were 955ms and 1186ms on that test setup; these are not performance guarantees. Earlier experiments observed a filesystem writeback stall after repeated snapshots; this transport work does not establish that issue's cause or resolution.

This is not enabled by default or provisioned automatically. Safe suspension eligibility, per-instance/fork key provisioning, reusable-browser teardown, and broader lifecycle/load validation remain required before general rollout. Command silence alone cannot establish that page work or an event waiter is safe to suspend.
